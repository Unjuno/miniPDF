### 2. 設計・コンセプト

#### [./CONCEPT.md](./CONCEPT.md)
**プロジェクトのコンセプト・設計思想**

- 目的と解決したい問題
  - Markdown を書きながら **PDF プレビュー**で最終見た目に近い状態を確認する
  - Mermaid を含むドキュメントの**ループを短くする**（編集 → プレビュー）
- 設計思想
  - PDFを「確認・保存用の成果物」として扱う
  - **PDF 上のレイアウト編集**は製品スコープ外（Markdown / 生成側で調整）
- 実装イメージ
  - アプリの性格（軽量 Markdown → PDF プレビュー）
  - 操作感（左エディタ、右プレビュー、ズーム・ページ送り）
- 技術スタックの方向性
  - Tauri + WebView（軽量・即起動）
  - PDFライブラリは「読む・描く」だけ

**読むべきタイミング**: プロジェクトの設計思想を理解したい時、なぜこのアプローチを選んだかを知りたい時

## ドキュメントの読み方

### 初めてプロジェクトを見る場合

1. **README.md** でプロジェクトの概要を把握
2. **CONCEPT.md** で設計思想と目的を理解
3. **SPECIFICATION.md** で機能仕様を確認
4. **CURRENT_ISSUES_SUMMARY.md** で既知の問題・リスクを確認（問題分析の正本）

### 実装を始める場合

1. **IMPLEMENTATION_PLAN.md** で実装の全体像を把握（AI開発支援用）
2. **SPECIFICATION.md** で機能仕様・実装方法の決定事項を確認
3. コードを参照しながら実装を進める

### AI開発支援ツールを使用する場合

1. **IMPLEMENTATION_PLAN.md** を主要コンテキストとして使用
2. 必要に応じて **SPECIFICATION.md** で詳細仕様を確認
3. コードベース構造とIPC通信仕様を参照
