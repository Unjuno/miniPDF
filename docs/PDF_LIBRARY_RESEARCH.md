# PDF編集ライブラリ調査結果（MCP調査版）

## 問題点

現在の実装では、`lopdf`を使用してPDFを生成していますが、元のPDFの構造（リソース、フォント、その他のオブジェクト）を保持するのが困難です。ページを削除した後に保存すると、元のPDFの情報が失われてしまいます。

## 調査したRust PDFライブラリ（MCP調査結果）

### 1. lopdf (現在使用中)
- **リポジトリ**: https://github.com/J-F-Liu/lopdf
- **特徴**: 低レベルなPDF操作が可能
- **問題点**: 
  - 既存のPDFを編集するのが難しい
  - リソースの保持が複雑
  - ページを削除すると構造が失われる
- **用途**: PDFの読み書き、基本的な操作
- **ライセンス**: Apache-2.0 / MIT

### 2. oxidize-pdf
- **リポジトリ**: https://github.com/bzsanti/oxidizePdf
- **特徴**: Pure Rust PDF生成・操作ライブラリ、外部PDF依存なし
- **利点**: 
  - PDFの読み込み、編集、分割、マージ、回転が可能
  - リソースの保持が可能（基本的な内容の保持）
  - 3,000-4,000ページ/秒の生成速度
  - 5.2MBのバイナリサイズ（軽量）
  - 破損PDFの回復機能（98.8%の成功率）
  - インクリメンタル更新機能（ISO 32000-1 §7.5.6準拠）
- **問題点**: 
  - **AGPL-3.0ライセンス**（商用利用には制限あり）
  - 現在のプロジェクトはMITライセンスのため、ライセンスの互換性に注意が必要
  - 商用ライセンスが必要な場合がある
- **用途**: PDF生成・編集・操作全般
- **ライセンス**: AGPL-3.0（商用ライセンスも提供）

### 3. printpdf
- **特徴**: PDF生成に特化
- **問題点**: 
  - 既存のPDFを読み込んで編集する機能が限定的
  - 主に新規PDF生成用
- **用途**: 新規PDF生成

### 4. pdfium-render
- **特徴**: PDFium（Google ChromeのPDFエンジン）のRustバインディング
- **利点**: 
  - 既存のPDFを読み込んで編集可能
  - リソースの保持が容易
  - 高機能なPDF操作
- **問題点**: 
  - バイナリサイズが大きい（PDFiumを含む）
  - ライセンスが複雑（BSD + その他）
- **用途**: 高機能なPDF編集が必要な場合

### 5. pdf-rs
- **特徴**: 軽量なPDF読み書きライブラリ
- **問題点**: 
  - 編集機能が限定的
  - 主に読み取り用
- **用途**: PDF読み取り

### 選択肢A: lopdfを継続使用（推奨）
- **理由**: 
  - 既に実装済み

  3. メタデータの保持（既に実装済み）

### 選択肢B: oxidize-pdfに移行（ライセンス要件を満たす場合）
- **理由**:

## 実装の詳細

### lopdfを使用する場合

元のPDFのリソースを保持するには、以下の手順が必要です：

1. 元のPDFを読み込む際に、各ページのリソースを抽出
2. リソースをマップに保存（フォント名、画像IDなど）
3. 新しいページを作成する際に、元のPDFのリソースを参照
4. リソースを新しいPDFにコピー

ただし、lopdfでは既存のオブジェクトを直接参照するのが難しいため、リソースをコピーする必要があります。

### oxidize-pdfを使用する場合

`oxidize-pdf`には以下の機能があります：

1. **インクリメンタル更新機能** (`write_incremental_update`)
   - 既存のPDFに新しいページを追加
   - 元のPDFの構造を保持

2. **ページ置換機能** (`write_incremental_with_page_replacement`)
   - 既存のPDFのページを置き換え
   - 元のPDFの構造を保持

3. **オーバーレイ機能** (`write_incremental_with_overlay`) - 計画中
   - 既存のPDFのページにコンテンツをオーバーレイ
   - 元のPDFの構造を保持

## 次のステップ

3. 既存のコードを`oxidize-pdf`のAPIに移行
4. インクリメンタル更新機能を使用して、元のPDFの構造を保持
5. テストを追加して、リソースが正しく保持されることを確認
