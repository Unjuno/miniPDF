# 現在の実装で起きうる問題 - エンジニア視点

この文書は、現在の実装で起きうる問題をエンジニア視点で分析したものです。

## 🔴 重大な問題（Critical Issues）

### 1. 日本語テキストの文字化け問題

**問題の詳細**:
- 非ASCII文字を含むテキストが、実際には標準フォント（Helvetica）で書き込まれている
- カスタムフォントの登録が実装されていない（TODOコメントのみ）
- 結果として、日本語テキストが文字化けする

**該当コード**:
```132:136:src-tauri/src/commands/pdf_generator.rs
if font_manager::is_font_available("NotoSansJP") {
    // TODO: oxidize-pdfの実際のAPIに合わせて実装
    // 例: Font::Custom("NotoSansJP".to_string())
    // 現時点では、標準フォントを使用（後でカスタムフォントに置き換え）
    Font::Helvetica
```

**影響**:
- 日本語を含むPDFを保存すると、テキストが文字化けする
- ユーザーが期待する結果が得られない

**推奨対応**:
- `oxidize-pdf`のAPIを確認し、カスタムフォントの埋め込み機能を実装する
- または、フォントが利用できない場合は、エラーを返すか、明確な警告を表示する

---

### 2. フォントレジストリの初期化タイミング問題

**問題の詳細**:
- フォントレジストリが`OnceLock`で初期化され、アプリケーション起動時に一度だけフォントを検出する
- 実行中にフォントファイルを追加しても認識されない
- 開発環境と本番環境でフォントディレクトリのパス解決が異なる可能性がある

**該当コード**:
```81:87:src-tauri/src/utils/font_manager.rs
fn get_registry() -> &'static FontRegistry {
    FONT_REGISTRY.get_or_init(|| {
        let mut registry = FontRegistry::new();
        registry.initialize_default_fonts();
        registry
    })
}
```

**影響**:
- 実行中にフォントファイルを追加しても反映されない
- 開発環境と本番環境で動作が異なる可能性がある

**推奨対応**:
- フォントディレクトリの再スキャン機能を追加する
- または、フォント検出を遅延評価にする（初回使用時に検出）

---

## 🟡 重要な問題（Important Issues）

### 3. エラーハンドリングの不備

**問題の詳細**:
- テストコードで`unwrap()`が使用されている（本番コードでは問題ないが、テストの堅牢性に影響）
- 一部のエラーが警告ログのみで処理され、ユーザーに通知されない

**該当コード**:
```122:122:src-tauri/src/commands/text_editor.rs
let updated = result.unwrap();
```

**影響**:
- テストが失敗した場合、詳細なエラー情報が得られない
- 一部のエラーがユーザーに通知されない

**推奨対応**:
- テストコードでも適切なエラーハンドリングを行う
- 重要なエラーはユーザーに通知する

---

### 4. メモリ使用量の問題

**問題の詳細**:
- 画像データがbase64エンコードされた文字列として保持されるため、メモリ効率が悪い
- 大きなPDFファイルをメモリに読み込む際のメモリ使用量が大きい可能性がある

**該当コード**:
```33:33:src-tauri/src/models/pdf_structure.rs
pub data: String,
```

**影響**:
- 大きなPDFファイルを処理する際にメモリ不足が発生する可能性がある
- アプリケーションのパフォーマンスが低下する

**推奨対応**:
- 画像データをストリーミング処理する
- または、画像データを一時ファイルに保存し、必要時に読み込む

---

### 5. 型安全性の問題

**問題の詳細**:
- TypeScriptで`any`型が使用されている（pdfjs, pdf）
- 型アサーション（`as string`）が多用されている

**該当コード**:
```81:81:src/stores/pdfStore.ts
const fileData = await readFile(filePath as string);
```

**影響**:
- 型安全性が損なわれる
- 実行時エラーのリスクが増加する

**推奨対応**:
- `any`型を適切な型に置き換える
- 型アサーションを最小限にする

---

## 🟢 軽微な問題（Minor Issues）

### 6. パフォーマンスの問題

**問題の詳細**:
- PDF生成が同期的に処理される（大きなPDFでUIがブロックされる可能性）
- 画像のbase64デコードが毎回行われる

**影響**:
- 大きなPDFファイルを処理する際にUIが固まる可能性がある

**推奨対応**:
- PDF生成をバックグラウンドスレッドで処理する
- 画像データのキャッシュを実装する

---

### 7. リソース管理の問題

**問題の詳細**:
- 元のPDFのリソース（フォント、画像）が保持されない
- `generate_pdf_with_preservation`と`generate_pdf_new`の実装が同じ

**該当コード**:
```37:40:src-tauri/src/commands/pdf_generator.rs
async fn generate_pdf_with_preservation(pdf: PdfStructure) -> Result<Vec<u8>, String> {
    // 注意: 将来的に元のPDFのリソース（フォント、画像など）を保持する機能を実装する予定
    // 現時点では、元のPDFを読み込むだけで、リソースの再利用は行っていない
    build_pdf_document(&pdf).await
}
```

**影響**:
- 元のPDFのリソースが失われる可能性がある
- ファイルサイズが増加する可能性がある

**推奨対応**:
- 元のPDFのリソースを保持する機能を実装する

---

### 8. 競合状態の問題

**問題の詳細**:
- 複数のPDF操作が同時に実行された場合の状態管理が不十分な可能性がある
- 非同期処理の順序が保証されていない

**影響**:
- 予期しない動作が発生する可能性がある

**推奨対応**:
- 操作の順序を保証する仕組みを実装する
- または、操作をキューイングする
