# 現在の実装で起きうる問題 - 詳細分析（エンジニア視点）

この文書は、現在の実装を詳細に分析し、エンジニア視点で発見された問題点をまとめたものです。

## 🔴 重大な問題（Critical Issues）

### 1. 日本語テキストの文字化け問題（未解決）

**現状**:
- カスタムフォントの登録が実装されていない（TODOコメントのみ）
- 非ASCII文字を含むテキストが標準フォント（Helvetica）で書き込まれる
- 警告ログは出力されるが、実際には文字化けが発生する

**技術的詳細**:
```rust
// src-tauri/src/commands/pdf_generator.rs:136-143
if font_manager::is_font_available("NotoSansJP") {
    // TODO: oxidize-pdfの実際のAPIに合わせて実装
    log::warn!("非ASCII文字を含むテキストを処理しますが、カスタムフォントの実装が未完了のため、文字化けする可能性があります");
    Font::Helvetica  // ← 実際には標準フォントを使用
}
```

**影響範囲**:
- 日本語を含むすべてのPDF保存操作
- ユーザーが期待する結果が得られない

**根本原因**:
- `oxidize-pdf`のAPIが未確認のため、カスタムフォントの埋め込み方法が不明

**推奨対応**:
1. `oxidize-pdf`のAPIドキュメントを確認
2. カスタムフォントの埋め込み機能を実装
3. フォントが利用できない場合は、エラーを返すか明確な警告をUIに表示

---

### 2. 状態管理の競合状態（Race Condition）

**問題の詳細**:
- `loadPdf`中に別の操作（`resizeImage`, `moveImage`など）が実行された場合、状態が不整合になる可能性がある
- Zustandストアの状態更新が非同期で、操作の順序が保証されていない

**該当コード**:
```typescript
// src/stores/pdfStore.ts:50-192
loadPdf: async (filePath: string) => {
  set({ pdfStructure: null, ... }); // ← 状態をクリア
  const structure = await invoke<PdfStructure>('load_pdf', { filePath });
  // ← この間に別の操作が実行される可能性がある
  const updatedPages = await Promise.all(...);
  set({ pdfStructure: updatedStructure, ... }); // ← 状態を更新
}
```

**問題シナリオ**:
1. ユーザーがPDFを読み込み中（`loadPdf`実行中）
2. ユーザーが画像をリサイズ（`resizeImage`実行）
3. `resizeImage`が古い`pdfStructure`を参照してエラーになる、または状態が上書きされる

**影響**:
- 予期しないエラーが発生する可能性
- ユーザーの操作が失われる可能性
- デバッグが困難

**推奨対応**:
- 操作をキューイングする（`loadPdf`中は他の操作をブロック）
- または、操作のロック機構を実装する
- または、各操作で`pdfStructure`の存在チェックとエラーハンドリングを強化

## 🟡 重要な問題（Important Issues）

### 3. メモリリークの可能性

**問題の詳細**:
- PDF.jsのPDFオブジェクトやページオブジェクトが適切にクリーンアップされていない可能性がある
- 大きなPDFファイルを複数回読み込むと、メモリ使用量が増加し続ける可能性がある

**該当コード**:
```typescript
// src/stores/pdfStore.ts:82-83
const loadingTask = pdfjs.getDocument({ data: fileData });
const pdf = await loadingTask.promise;
// ← pdfオブジェクトの参照が保持され続ける可能性がある
```

**影響**:
- 長時間使用するとメモリ不足が発生する可能性
- アプリケーションのパフォーマンスが低下する

**推奨対応**:
- PDFオブジェクトの参照を適切に管理する
- `pdf.destroy()`を呼び出してリソースを解放する
- または、WeakMapを使用して参照を管理する

---

### 4. エラー回復の不備

**問題の詳細**:
- PDF.jsのテキスト抽出に失敗した場合、フォールバック処理が不完全
- エラーが発生しても処理が続行され、不完全なデータが保存される可能性がある

**該当コード**:
```typescript
// src/stores/pdfStore.ts:143-149
} catch (error) {
  logger.warn('PDF.js text extraction failed, using backend result', { ... });
  textBlocks = page.textBlocks; // ← バックエンドの結果を使用
}
// ← エラーが発生しても処理が続行される
```

**影響**:
- 不完全なデータが保存される可能性
- ユーザーがエラーに気づかない可能性

**推奨対応**:
- エラーが発生した場合、ユーザーに通知する
- または、エラーが発生した場合は処理を中断するオプションを提供する

---

### 5. 非同期処理の順序保証

**問題の詳細**:
- 複数の操作が同時に実行された場合、処理の順序が保証されていない
- 例: `resizeImage`と`moveImage`が同時に実行された場合、どちらが先に適用されるか不明

**該当コード**:
```typescript
// src/stores/pdfStore.ts:198-244
resizeImage: async (imageId: string, width: number, height: number) => {
  const state = get(); // ← この時点の状態を取得
  const updatedImage = await invoke<ImageElement>('resize_image', { ... });
  set({ pdfStructure: updatedPdfStructure }); // ← 状態を更新
}
// ← この間に別の操作が実行される可能性がある
```

**影響**:
- 予期しない動作が発生する可能性
- ユーザーの操作が失われる可能性

**推奨対応**:
- 操作をキューイングする
- または、各操作で状態のバージョン管理を行う（楽観的ロック）

---

### 6. メモリ使用量の問題（詳細）

**問題の詳細**:
- 画像データがbase64エンコードされた文字列として保持されるため、メモリ効率が悪い
- base64エンコードにより、元のバイナリデータの約33%増加
- 大きなPDFファイルをメモリに読み込む際のメモリ使用量が大きい

**該当コード**:
```rust
// src-tauri/src/models/pdf_structure.rs:33
pub data: String, // ← base64エンコードされた文字列
```

**計算例**:
- 10MBの画像 → base64エンコードで約13.3MB
- 100ページのPDF（各ページに1MBの画像）→ 約1.3GBのメモリ使用量

**影響**:
- 大きなPDFファイルを処理する際にメモリ不足が発生する可能性
- アプリケーションのパフォーマンスが低下する

**推奨対応**:
- 画像データをストリーミング処理する
- または、画像データを一時ファイルに保存し、必要時に読み込む
- または、画像データを圧縮する

## 🟢 軽微な問題（Minor Issues）

### 7. リソースのクリーンアップ不足

**問題の詳細**:
- PDF.jsのPDFオブジェクトやページオブジェクトのクリーンアップが不十分
- コンポーネントのアンマウント時にリソースが解放されない可能性がある

**該当コード**:
```typescript
// src/components/PDFViewer.tsx:462
const pdf = await loadingTask.promise;
pdfDocRef.current = pdf;
// ← コンポーネントのアンマウント時にpdf.destroy()が呼ばれていない可能性がある
```

**影響**:
- メモリリークの可能性
- 長時間使用するとパフォーマンスが低下する

**推奨対応**:
- `useEffect`のクリーンアップ関数で`pdf.destroy()`を呼び出す
- または、WeakMapを使用して参照を管理する

---

### 8. エラーハンドリングの一貫性

**問題の詳細**:
- エラーハンドリングの方法が一貫していない
- 一部のエラーは警告ログのみ、一部のエラーはユーザーに通知される

**影響**:
- ユーザーがエラーに気づかない可能性
- デバッグが困難

**推奨対応**:
- エラーハンドリングのポリシーを統一する
- 重要なエラーは必ずユーザーに通知する
