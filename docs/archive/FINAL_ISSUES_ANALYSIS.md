## 🔴 重大な問題（Critical Issues）

### 1. 編集内容が保存されない問題（✅ 修正済み - 2024年12月22日）

**問題の詳細**:
- `savePdf`関数で未定義の変数`pdfStructure`を参照していた
- 編集操作（画像のリサイズ、移動、テキスト編集など）がPDFに反映されなかった
- プレビュー用途でしか使えない状態だった

**技術的詳細**:
```437:439:src/stores/pdfStore.ts
const pdfData = await invoke<number[]>('generate_pdf', {
  pdfStructure,  // ← 未定義の変数を参照
});
```

**影響範囲**:
- すべての編集操作が保存されない
- ユーザーが編集した内容がPDFに反映されない
- アプリケーションが実用的でない状態

**根本原因**:
- `state.pdfStructure`を使うべきところで、未定義の変数`pdfStructure`を参照していた

**修正内容**:
- `state.pdfStructure`を明示的に取得して使用するように修正
- 操作完了時に最新の状態を再取得してからPDFを生成

**該当コード（修正後）**:
```typescript
const currentState = get();
if (!currentState.pdfStructure) {
  set({ isEditing: false });
  throw new Error('PDFが読み込まれていません');
}

const pdfData = await invoke<number[]>('generate_pdf', {
  pdfStructure: currentState.pdfStructure,  // ← 最新の状態を使用
});
```

**効果**:
- 編集操作が正しくPDFに反映される
- アプリケーションが実用的になった

## 🟡 重要な問題（Important Issues）

### 2. メモリ使用量の問題（未解決）

**問題の詳細**:
- 画像データがbase64エンコードされた文字列として保持されるため、メモリ効率が悪い
- base64エンコードにより、元のバイナリデータの約33%増加
- 大きなPDFファイルをメモリに読み込む際のメモリ使用量が大きい

**該当コード**:
```33:33:src-tauri/src/models/pdf_structure.rs
pub data: String, // ← base64エンコードされた文字列
```

**計算例**:
- 10MBの画像 → base64エンコードで約13.3MB
- 100ページのPDF（各ページに1MBの画像）→ 約1.3GBのメモリ使用量

**影響**:
- 大きなPDFファイルを処理する際にメモリ不足が発生する可能性
- アプリケーションのパフォーマンスが低下する
- メモリ制限のある環境で動作しない可能性

**推奨対応**:
- 画像データをストリーミング処理する
- または、画像データを一時ファイルに保存し、必要時に読み込む
- または、画像データを圧縮する
- または、画像データを`Vec<u8>`として保持し、base64エンコードは必要時のみ行う

**影響**:

- `invoke`の結果を直接使用（バックエンドが正しい状態を返す）

**該当ファイル**: `src/stores/pdfStore.ts`
**効果**: 
  - 状態の不整合を防ぐ
  - 操作中にPDFが削除された場合の適切な処理
  - より安全な状態管理

- より堅牢なエラーハンドリング
- ユーザーエクスペリエンスの向上

**修正日**: 2024年
